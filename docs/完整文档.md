## 1. 概述

### 1.1 项目背景

AutoGLM测试框架是基于Open-AutoGLM API的自动化测试解决方案，专门针对移动应用UI自动化测试场景设计。与传统自动化测试工具不同，本框架直接调用AutoGLM的AI能力，通过自然语言描述驱动设备操作，大大降低了测试用例的编写门槛。

### 1.2 核心价值

- **低代码测试**：测试用例以CSV/Excel格式管理，非技术人员可轻松编写
- **AI驱动**：利用AutoGLM视觉大模型理解UI并执行操作，无需编写元素定位代码
- **双格式报告**：同时生成可视化HTML报告和机器可读JSON报告
- **开箱即用**：完整的设备检查、错误处理、截图保存等功能

### 1.3 适用场景

- 移动应用回归测试
- 业务流程自动化验证
- 烟点功能验收测试
- 夜间定时任务执行

### 4.2 关键技术点

#### 4.2.1 直接API调用

**传统方式** (excel_test_manager.py)：
```python
cmd = f"python main.py --base-url {url} --device-id {device} '{task}'"
result = subprocess.run(cmd, shell=True)
```

**新方式** (api_executor.py)：
```python
from phone_agent import PhoneAgent
from phone_agent.model import ModelConfig

model_config = ModelConfig(
    base_url=config.api.base_url,
    model_name=config.api.model_name,
    api_key=config.api.api_key
)

agent = PhoneAgent(model_config=model_config, agent_config=agent_config)
result = agent.run(task)  # 直接Python调用
```

**优势**：
- 性能提升30-50%
- 更好的错误处理
- Agent实例复用
- 支持并发执行

#### 4.2.2 增强验证逻辑

```python
class EnhancedValidator:
    def validate_autoGLM_result(self, output, expected_results, test_data):
        # 1. 关键词验证
        for expected in expected_results:
            if expected not in output:
                return False, "未找到关键词: " + expected

        # 2. 金额验证（允许±0.5误差）
        if "预期金额" in test_data:
            actual_amount = extract_amount(output)
            expected = float(test_data["预期金额"])
            if abs(actual_amount - expected) > 0.5:
                return False, "金额不匹配"

        # 3. 业务数据验证
        if "农户" in test_data:
            if test_data["农户"] not in output:
                return False, "农户验证失败"

        return True, validation_details
```

#### 4.2.3 设备健康检查

```python
def _check_devices(self):
    device_factory = get_device_factory()
    devices = device_factory.list_devices()

    for device in devices:
        # 检查状态
        if device.status != "device":
            return False, f"设备状态异常: {device.status}"

        # 测试截图功能
        screenshot = device_factory.get_screenshot(device.device_id)
        if not screenshot:
            return False, "截图功能异常"

    return True
```

#### 4.2.4 失败截图保存

```python
def _save_failure_screenshot(self, test_case):
    # 获取截图
    device_factory = get_device_factory()
    screenshot = device_factory.get_screenshot(test_case.device_id)

    # 保存为PNG文件
    timestamp = time.strftime("%Y%m%d_%H%M%S")
    filename = f"{test_case.test_id}_{timestamp}.png"
    screenshot_path = os.path.join(screenshot_dir, filename)

    image_data = base64.b64decode(screenshot.base64_data)
    with open(screenshot_path, 'wb') as f:
        f.write(image_data)

    return screenshot_path
```

## 6. 使用指南

### 6.1 安装依赖

```bash
# 安装Python依赖
pip install pyyaml openai

# 或使用项目虚拟环境
source venv/bin/activate
pip install -r requirements.txt
```

### 6.2 准备工作

#### 1. 设备准备
- 连接Android设备并开启USB调试
- 授权电脑进行USB调试
- 安装需要测试的应用（如森果产地通）

#### 2. 准备测试用例CSV文件

CSV格式规范：
```csv
测试用例ID,测试名称,测试类型,优先级,前置条件,测试步骤,预期结果,测试数据,任务超时时间,标签,设备ID
TC-P001,新建采购单,采购单,P1,设备已连接,打开森果产地通...,✅任务完成 ✅金额:7元,"农户:非伍6,预期金额:7",180,smoke,PQY5T20A07017811
```

字段说明：
- **测试用例ID**: 唯一标识符
- **测试步骤**: 自然语言描述的操作步骤
- **预期结果**: 空格分隔的验证条件
- **测试数据**: 键值对格式（key:value）
- **设备ID**: 目标设备ID

#### 3. 配置API密钥

方式一：设置环境变量
```bash
export AUTOGLM_API_KEY="your_api_key"
```

方式二：修改配置文件
```yaml
api:
  api_key: "your_api_key"
```

### 6.3 基本使用

#### 运行所有测试
```bash
python api_test_runner.py --csv "测试用例.csv"
```

#### 筛选运行
```bash
# 只运行smoke测试
python api_test_runner.py --csv "测试用例.csv" --filter-tags smoke

# 只运行P1优先级测试
python api_test_runner.py --csv "测试用例.csv" --filter-priority P1

# 指定设备运行
python api_test_runner.py --csv "测试用例.csv" --device-id PQY5T20A07017811
```

#### 高级选项
```bash
# 失败后继续执行
python api_test_runner.py --csv "测试用例.csv" --continue-on-failure

# 跳过设备检查（不推荐）
python api_test_runner.py --csv "测试用例.csv" --skip-device-check

# 使用自定义配置文件
python api_test_runner.py --csv "测试用例.csv" --config my_config.yaml

# 指定输出目录
python api_test_runner.py --csv "测试用例.csv" --output-dir my_reports
```

### 6.4 查看报告

测试完成后会生成两类报告：

**HTML报告**（可视化）：
- 文件位置：`test_reports/html/test_report_YYYYMMDD_HHMMSS.html`
- 包含：测试汇总、详细步骤、验证结果、失败截图
- 在浏览器中打开查看

**JSON报告**（机器可读）：
- 文件位置：`test_reports/json/test_report_YYYYMMDD_HHMMSS.json`
- 包含：完整的执行数据、验证详情、设备信息
- 可用于CI/CD集成

## 8. 常见问题

### Q1: 如何查看连接的设备？

```bash
adb devices -l
```

### Q2: 设备检查失败怎么办？

**错误示例**：
```
❌ 设备检查失败:
  - 未找到已连接的设备
  - 设备 PQY5T20A07017811 截图失败
```

**解决方案**：
1. 检查USB连接
2. 确认USB调试已开启
3. 在设备上授权USB调试
4. 重启adb服务：`adb kill-server && adb start-server`

### Q3: API调用失败怎么办？

**错误示例**：
```
Model error: Error code: 401
```

**解决方案**：
1. 检查API密钥是否正确
2. 确认账户余额充足
3. 检查网络连接

### Q4: 测试验证失败但实际成功了？

**原因**：预期结果与实际输出不匹配

**解决方案**：
- 检查预期结果中的关键词是否正确
- 调整验证规则，使用模糊匹配
- 查看`validation_details`了解具体失败原因

### Q5: 如何调试单个测试用例？

```bash
# 运行单个测试并查看详细输出
python api_test_runner.py --csv "测试用例.csv" --filter-tags smoke --verbose
```

### Q6: 支持哪些设备类型？

当前支持：
- **Android设备**：通过ADB连接
- **HarmonyOS设备**：通过HDC连接（需设置 `--device-type hdc`）

未来计划：
- iOS设备（通过WebDriverAgent）

## 9. 最佳实践

### 9.1 测试用例设计

#### DO（推荐做法）
- ✅ 测试步骤使用清晰的自然语言描述
- ✅ 预期结果明确，包含可验证的关键词
- ✅ 测试数据结构化（键值对格式）
- ✅ 合理设置超时时间（根据操作复杂度）
- ✅ 添加适当的标签（smoke, regression等）

#### DON'T（避免做法）
- ❌ 测试步骤过于复杂，难以拆解
- ❌ 预期结果模糊不清
- ❌ 超时时间设置过短
- ❌ 测试数据格式混乱

### 9.2 设备管理

- 建议使用固定设备ID，避免动态变化
- 定期检查设备状态和授权
- 测试前确认设备电量充足
- 避免设备过热，适当间隔测试

### 9.3 性能优化

- 同一设备串行执行，避免并发冲突
- 不同设备可并行执行，提升效率
- 使用Agent实例复用，减少初始化开销
- 合理设置max_steps，避免无限循环

### 9.4 错误处理

- 使用`--continue-on-failure`批量运行时注意分析失败原因
- 失败截图是关键调试信息
- JSON报告可用于后续分析
- 结合verbose日志定位问题

### 9.5 CI/CD集成

```yaml
# .github/workflows/test.yml 示例
name: AutoGLM Test

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Setup Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.9'

      - name: Install dependencies
        run: |
          pip install pyyaml openai

      - name: Run AutoGLM Tests
        env:
          AUTOGLM_API_KEY: ${{ secrets.AUTOGLM_API_KEY }}
        run: |
          python api_test_runner.py --csv test_cases.csv --continue-on-failure

      - name: Upload Reports
        uses: actions/upload-artifact@v4
        with:
          name: Test Reports
          path: test_reports/
```
